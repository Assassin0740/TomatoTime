## 1. 测试策略

本项目未引入测试框架，采用**分层手工验证**：静态检查 → 引用校验 → 运行时冒烟 → 专项测试。

```
Level 1  语法检查       node --check / 内联脚本解析         ← 秒级，每次改动必做
Level 2  引用完整性      HTML id ↔ JS getElementById 比对    ← 秒级，改 HTML 后必做
Level 3  启动冒烟        实际启动 Electron + 页面探针          ← 约 15 秒
Level 4  专项测试        悬浮窗 / 计时器等关键链路独立验证      ← 按需
```

**为什么不用测试框架**：项目无构建流程、无模块系统，引入测试框架需要改造源码结构。当前阶段以"可执行的验证脚本 + 明确的检查清单"替代，成本更低（详见 `09` 的改进建议）。

### 2.2 引用完整性（Level 2）

| 用例 | 检查项 | 通过标准 |
|---|---|---|
| TC-R-01 | `renderer.js` 中 `getElementById('x')` 引用的 id 全部存在于 HTML | 缺失列表为空 |
| TC-R-02 | 动态拼接的 id 前缀已覆盖 | 人工核对 |

**TC-R-01 可复用脚本**

```bash
node -e "
const fs=require('fs');
const html=fs.readFileSync('计时器.html','utf8');
const js=fs.readFileSync('renderer.js','utf8');
const htmlIds=new Set([...html.matchAll(/id=\"([^\"]+)\"/g)].map(m=>m[1]));
const used=[...new Set([...js.matchAll(/getElementById\(['\"]([^'\"]+)['\"]\)/g)].map(m=>m[1]))];
const missing=used.filter(id=>!htmlIds.has(id));
console.log('HTML 中 id 数量:', htmlIds.size);
console.log('JS 引用 id 数量:', used.length);
console.log('缺失的 id:', missing.length? missing : '无 ✅');
"
```

> **为什么要做这一层**：`renderer.js` 通过 `getElementById(...).onclick = ...` 绑定事件，一旦 id 缺失会**静默失效或直接抛错**。这是在"折叠收纳"重构中风险最高的地方。

**TC-B 执行方法**

```bash
# 1) 在 renderer.js 末尾临时加入探针
console.log('__RENDERER_READY__' + JSON.stringify({
    toolPanel: !!document.getElementById('toolPanel'),
    summaryText: document.getElementById('toolPanelSummary')?.textContent,
    addNoteBtn: !!document.getElementById('addNoteBtn'),
    floatShowTask: !!document.getElementById('floatShowTask'),
    /* …其他待验证元素… */
}));

# 2) 启动并捕获输出（无头环境需禁用 GPU）
ELECTRON_ENABLE_LOGGING=1 ./node_modules/.bin/electron . \
    --user-data-dir="./_probe" \
    --disable-gpu --disable-gpu-compositing \
    --disable-software-rasterizer --in-process-gpu > ./_probe.log 2>&1 &

# 3) 等待约 15 秒后读取
grep -o "__RENDERER_READY__.*" ./_probe.log | head -1
grep -iE "uncaught|typeerror|is not a function|cannot read" ./_probe.log

# 4) 测试完成后务必删除探针代码与临时目录
```

> ⚠️ **重要**：探针代码是**临时**的，验证完成后必须删除，否则会污染生产代码。

### 3.3 过程中遇到的问题

| 问题 | 说明 | 处理 |
|---|---|---|
| GPU 进程 FATAL | 无头环境下 Electron GPU 进程崩溃 | 非改动引入，属环境已知问题；追加 `--disable-gpu` 系列参数后正常启动 |
| 渲染进程 console 不可见 | 未开启日志时看不到页面输出 | 设置 `ELECTRON_ENABLE_LOGGING=1` |
| CDP 远程调试端口未启动 | 尝试通过调试协议读取页面状态失败 | 改用"页面内探针 + 日志捕获"的替代方案，成功拿到运行时状态 |

> **经验沉淀**：在无头 / 自动化环境下验证 Electron 渲染进程，"页面内探针 + `ELECTRON_ENABLE_LOGGING=1` + 日志捕获"是最稳定可行的路径，比远程调试协议更可靠。

## 4. 质量门禁（DoD · 完成的定义）

任何变更在标记"完成"前，必须通过以下全部检查：

```
□ 功能按需求实现，验收标准满足
□ node --check 语法检查通过（main.js / renderer.js）
□ float.html 内联脚本语法检查通过（若涉及）
□ HTML id ↔ JS 引用完整性校验通过（若涉及 HTML）
□ 启动冒烟测试通过，无未捕获异常
□ 若涉及任务内容处理 → 图片保留验证通过
□ 若修改了 计时器.html → index.html 已同步且 md5 一致
□ 临时探针代码、测试脚本、日志、临时目录已清理
□ 相关文档已更新（需求 / 架构 / 进度 / 变更）
```
