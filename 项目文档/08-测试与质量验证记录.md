## 1. 测试策略

本项目采用**分层验证**：静态检查 → 引用校验 → 运行时冒烟 → 专项测试 → 单元测试（2026-09-11 起，Node 原生 `node:test`）。

```
Level 1  语法检查       node --check / 内联脚本解析         ← 秒级，每次改动必做
Level 2  引用完整性      HTML id ↔ JS getElementById 比对    ← 秒级，改 HTML 后必做
Level 3  启动冒烟        实际启动 Electron + 页面探针          ← 约 15 秒
Level 4  专项测试        悬浮窗 / 计时器等关键链路独立验证      ← 按需
Level 5  单元测试        node --test tests/*.test.js          ← 存储层已覆盖（store.js 23 用例）
```

**为什么只用 Node 原生 `node:test`**：项目无构建流程，`node:test` 零依赖、零配置，与"改完即生效"的开发体验不冲突。渲染端逻辑（依赖 DOM / Electron）暂不适用，先用运行时探针覆盖。

**TC-R-01 可复用脚本**

```bash
node -e "
const fs=require('fs');
const html=fs.readFileSync('计时器.html','utf8');
const js=fs.readFileSync('renderer.js','utf8');
const htmlIds=new Set([...html.matchAll(/id=\"([^\"]+)\"/g)].map(m=>m[1]));
const used=[...new Set([...js.matchAll(/getElementById\(['\"]([^'\"]+)['\"]\)/g)].map(m=>m[1]))];
const missing=used.filter(id=>!htmlIds.has(id));
console.log('HTML 中 id 数量:', htmlIds.size);
console.log('JS 引用 id 数量:', used.length);
console.log('缺失的 id:', missing.length? missing : '无 ✅');
"
```

> **为什么要做这一层**：`renderer.js` 通过 `getElementById(...).onclick = ...` 绑定事件，一旦 id 缺失会**静默失效或直接抛错**。这是在"折叠收纳"重构中风险最高的地方。

### 2.6 行为验证（Level 4 · 主进程内置探针）

对于**主计时循环**这类核心逻辑，静态检查无法覆盖，需要真实运行时验证。做法是：在主进程内置一段临时探针（用环境变量开关控制），周期性采样状态，跑完后删除。

| 用例 | 检查项 | 通过标准 |
|---|---|---|
| TC-B-10 | 开启「自动开始下一阶段」，短阶段时长下连续观察 | 阶段连续切换，末态 `isRunning === true` |
| TC-B-11 | 关闭「自动开始下一阶段」，同条件观察 | 只切换一次后停止，末态 `isRunning === false` |

**探针骨架（可复用）**

```js
// 挂在 main.js 末尾，验证完必须删除
if (process.env.AUTOSTART_TEST === '1') {
    app.whenReady().then(async () => {
        const sleep = ms => new Promise(r => setTimeout(r, ms));
        const samples = [];
        const tick = setInterval(() => { samples.push(Object.assign({ t: Date.now() }, getTimerStatus())); }, 200);

        await sleep(3000);
        WORK_TIME = 3; REST_TIME = 3;          // 阶段缩短到 3 秒，便于观察

        autoStartNext = true;                   // 阶段 1：开启
        samples.length = 0;
        setTimerTime(0, 3); toggleTimer();
        const t0 = Date.now();
        await sleep(11000);
        const p1 = samples.filter(s => s.t >= t0);
        let n1 = 0;
        for (let i = 1; i < p1.length; i++) if (p1[i - 1].isWorking !== p1[i].isWorking) n1++;
        console.log('__P1_TRANSITIONS__' + n1 + ' / RUNNING=' + p1[p1.length - 1].isRunning);

        autoStartNext = false;                  // 阶段 2：关闭
        samples.length = 0;
        setTimerTime(0, 3); toggleTimer();
        const t1 = Date.now();
        await sleep(8000);
        const p2 = samples.filter(s => s.t >= t1);
        let n2 = 0;
        for (let i = 1; i < p2.length; i++) if (p2[i - 1].isWorking !== p2[i].isWorking) n2++;
        console.log('__P2_TRANSITIONS__' + n2 + ' / RUNNING=' + p2[p2.length - 1].isRunning);

        clearInterval(tick);
        app.exit(0);
    });
}
```

### 2.7 ⚠️ 本机验证 Electron 的两个环境陷阱（必读）

在 WorkBuddy 会话里直接跑 `electron .` 会失败，**不是代码问题**，而是环境所致。已定位并记录为 `06` I-16：

| 陷阱 | 现象 | 原因 | 处置 |
|---|---|---|---|
| **`ELECTRON_RUN_AS_NODE=1`** | 启动即 `TypeError: Cannot read properties of undefined (reading 'requestSingleInstanceLock')` | WorkBuddy CLI 会注入该变量，使 `electron.exe` 退化成**纯 Node** 运行，`require('electron')` 拿不到 `app` | 启动前 `delete env.ELECTRON_RUN_AS_NODE`（同时剔除 `NODE_OPTIONS` / `NODE_PATH`） |
| **中文路径编码** | 报错里路径变成 `璁℃椂鍣╘main.js`（UTF-8 被按 GBK 解读） | Git Bash 向原生 Electron 传 cwd / 参数时编码转换有损 | 用 **node 的 `spawn` 显式传 `cwd`**（走 UTF-16 的 `CreateProcessW`），并直接调用 `node_modules/electron/dist/electron.exe` |

**可复用的启动器（`_run.js`，验证后删除）**

```js
const { spawn } = require('child_process');
const fs = require('fs');
const path = require('path');

const root = __dirname;
const fd = fs.openSync(path.join(root, '_test.log'), 'w');

const env = Object.assign({}, process.env, { AUTOSTART_TEST: '1' });
delete env.ELECTRON_RUN_AS_NODE;   // ← 关键
delete env.NODE_OPTIONS;
delete env.NODE_PATH;

spawn(
    path.join(root, 'node_modules', 'electron', 'dist', 'electron.exe'),
    ['.', '--user-data-dir=./_testdata', '--disable-gpu',
     '--disable-gpu-compositing', '--disable-software-rasterizer', '--in-process-gpu'],
    { cwd: root, env, stdio: ['ignore', fd, fd] }
);
```

运行：`node _run.js`，等待约 30 秒后读取 `_test.log`。
