## CR-001 · 主界面低频控件折叠收纳

| 项 | 内容 |
|---|---|
| **提出日期** | 2026-09-11 |
| **提出人** | 项目所有者 |
| **类型** | 优化（界面 / 可用性） |
| **优先级** | 中 |
| **状态** | ✅ 已完成 |

### 变更理由

主界面控件堆叠过多：4 层筛选/排序区（排序 3 按钮 + 筛选下拉、视图切换 2 按钮、日期范围 3 按钮 + 2 日期框、类型筛选 3 按钮），加上输入区的优先级 3 项 / 类型 2 项 / 操作按钮 4 个。首屏信息密度过高，核心操作（输入任务）被淹没。

### 变更内容

把 6 组低频控件收进一个新的折叠面板 `toolPanel`，**默认收起**：

| 收纳控件 | 原位置 |
|---|---|
| 排序（时间 / 紧急 / 未完成） | 列表上方 |
| 状态筛选下拉 | 列表上方 |
| 视图切换（卡片 / 表格） | 输入区下方 |
| 任务类型筛选（全部 / 短期 / 长期） | 输入区下方 |
| 日期范围筛选（本周 / 全部时间 / 自定义） | 输入区下方 |
| 批量操作（清空 / 归档已完成 / 导出） | 输入区按钮行 |

**保留在首屏**：计时器、任务输入框、优先级、类型、「添加」按钮。

附加设计：
- 折叠头右侧显示状态摘要（如「卡片 · 本周」），收起状态也能看到当前筛选条件
- 展开/收起状态与筛选状态均持久化

### 影响分析

| 维度 | 影响 |
|---|---|
| 涉及文件 | `计时器.html`（+ `index.html` 同步）、`style.css`、`renderer.js` |
| 兼容性 | 所有元素 `id` 保持不变，不破坏 `renderer.js` 的事件绑定 |
| 交互逻辑 | 筛选下拉菜单从"绝对定位下拉"改为在折叠面板内正常布局（规避 `.collapsible-content` 的 `max-height` + `overflow:hidden` 裁剪问题） |
| 数据 | 无数据格式变更，无迁移需求 |
| 风险 | 元素 ID 缺失会导致绑定失败 → 通过引用完整性校验规避 |

### 验证结果

- ✅ 语法检查通过
- ✅ 元素引用完整性校验：HTML 中 id 与 JS 引用全部匹配
- ✅ 运行时探针确认：`toolPanel`、`toolPanelSummary`、各按钮与函数均就位；摘要显示"卡片 · 本周"
- ✅ 启动冒烟测试通过

## CR-002 · 悬浮窗显示任务图片 + 内容开关

| 项 | 内容 |
|---|---|
| **提出日期** | 2026-09-11 |
| **提出人** | 项目所有者 |
| **类型** | 功能新增 |
| **优先级** | 中 |
| **状态** | ✅ 已完成 |

### 变更理由

任务内容本身是 HTML，可包含图片，但悬浮窗用 `stripHtml()` 把内容强制转为纯文本，图片完全无法显示。用户希望悬浮窗能展示任务中的图片，并提供开关控制。

### 变更内容

| 功能 | 说明 |
|---|---|
| 显示任务图片 | 从当前任务 `content` 的 HTML 中提取 `<img>`，在任务文字下方渲染为缩略图 |
| 数量上限 | 超出上限的部分显示 `+N` 角标 |
| 点击放大 | 点击图片在悬浮窗内临时放大，再点一次还原 |
| 开关 1：显示任务 | 关闭后任务区与分隔线一起隐藏，悬浮窗只剩时钟 |
| 开关 2：显示任务图片 | 关闭后只显示文字 |
| 设置项 3：最多显示图片 | 1–6 张，默认 3 |
| 自动撑高 | 开启图片且窗口高度 <160px 时自动调整到 170px，保证图片可见 |

设置入口：主界面 **⚙ → 悬浮窗设置**。

### 影响分析

| 维度 | 影响 |
|---|---|
| 涉及文件 | `float.html`、`计时器.html`（+ `index.html` 同步）、`renderer.js`、`main.js`、`style.css` |
| 新增 localStorage 键 | `floatShowTask`、`floatShowImages`、`floatImageLimit` |
| 新增 IPC 频道 | `float-content-settings`（主 → 悬浮窗）、`update-float-content-settings`（渲染 → 主） |
| 同步方式 | 沿用既有"设置存主窗口 localStorage → 主进程 `executeJavaScript` 读取 → 推送悬浮窗"模式 |
| 窗口约束 | 未修改 150–700 × 50–250 的范围限制；新增 `ensureFloatWindowFitsImages()` 做高度兜底 |
| 风险 | 图片提取需正确处理 `file://` 路径与相对路径两种 src |

### 验证结果

- ✅ `float.html` 内联脚本语法检查通过
- ✅ 悬浮窗独立运行时测试：图片成功真实加载（实测渲染宽度 1052px）
- ✅ 开关逻辑验证：关闭任务区后任务区正确隐藏
- ✅ 主界面初始化探针确认三个设置控件全部就位

|---|---|

| 方案 | 做法 | 优点 | 缺点 |

| C | 增加构建前校验脚本，检测两份文件是否一致 | 保留双份 | 未从根本解决，仍需同步 |

### 变更内容

| 编号 | 类型 | 内容 |
|---|---|---|
| **新增功能** | 功能 | 设置面板新增「自动开始下一阶段」开关（**默认关闭**，保持原有行为不变） |
| **I-02** | 体验 | 悬浮窗时间数字的"阴影大小"由 `box-shadow`（矩形光晕块）改为真正的 `text-shadow`，并通过 CSS 变量与"发光"效果**叠加**而非互相覆盖 |
| **I-03** | 体验 | 悬浮窗右键菜单改名为「设置悬浮窗配图… / 清除悬浮窗配图」，与"任务图片"概念区分 |

| **I-06** | 一致性 | "关于"对话框版本号由硬编码 `v1.0.0` 改为 `app.getVersion()`，从 `package.json` 动态读取 |
| **CR-006** | 重构 | 删除 `index.html` |

### 影响分析

| 维度 | 影响 |
|---|---|
| 涉及文件 | `计时器.html`（新增开关 UI）、`renderer.js`（读写 `localStorage.autoStartNext` + IPC 推送）、`main.js`（`autoStartNext` 状态 + 归零分支逻辑 + `app.getVersion()`）、`float.html`（阴影实现） |
| 数据兼容 | `localStorage` 新增键 `autoStartNext`，缺省为 `false`，**对历史数据零影响、无迁移** |
| 行为兼容 | 默认关闭 → 未主动开启的用户行为与改动前完全一致 |
| 风险 | 归零分支涉及主计时循环，属核心逻辑 → 必须有运行时验证 |

### 关键技术细节

```js
// main.js · 归零分支
if (currentTime <= 0) {
    // 先发 end 通知（发的是刚结束的状态），再翻转 isWorking —— 顺序写反会响错提示音
    if (mainWindow && !mainWindow.isDestroyed()) {
        mainWindow.webContents.send('timer-end', { isWorking: isWorking });
    }
    isWorking = !isWorking;
    currentTime = isWorking ? WORK_TIME : REST_TIME;

    if (autoStartNext) {
        // 不动 interval，让它继续跑下去；
        // 且不重置 lastTime，使不足 1 秒的余量带到下一阶段，避免累积漂移
    } else {
        clearInterval(timerInterval);
        timerInterval = null;
        isTimerRunning = false;
    }
    updateTrayMenu();
}
```

> `isRunning` 由 `timerInterval !== null` 推导，因此"保留 interval"本身就等于"仍在运行"，无需额外状态。

### 验证结果（运行时实测，非纯静态检查）

| 场景 | 预期 | 实测 |
|---|---|---|
