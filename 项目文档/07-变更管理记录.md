## CR-001 · 主界面低频控件折叠收纳

| 项 | 内容 |
|---|---|
| **提出日期** | 2026-09-11 |
| **提出人** | 项目所有者 |
| **类型** | 优化（界面 / 可用性） |
| **优先级** | 中 |
| **状态** | ✅ 已完成 |

### 变更理由

主界面控件堆叠过多：4 层筛选/排序区（排序 3 按钮 + 筛选下拉、视图切换 2 按钮、日期范围 3 按钮 + 2 日期框、类型筛选 3 按钮），加上输入区的优先级 3 项 / 类型 2 项 / 操作按钮 4 个。首屏信息密度过高，核心操作（输入任务）被淹没。

### 变更内容

把 6 组低频控件收进一个新的折叠面板 `toolPanel`，**默认收起**：

| 收纳控件 | 原位置 |
|---|---|
| 排序（时间 / 紧急 / 未完成） | 列表上方 |
| 状态筛选下拉 | 列表上方 |
| 视图切换（卡片 / 表格） | 输入区下方 |
| 任务类型筛选（全部 / 短期 / 长期） | 输入区下方 |
| 日期范围筛选（本周 / 全部时间 / 自定义） | 输入区下方 |
| 批量操作（清空 / 归档已完成 / 导出） | 输入区按钮行 |

**保留在首屏**：计时器、任务输入框、优先级、类型、「添加」按钮。

附加设计：
- 折叠头右侧显示状态摘要（如「卡片 · 本周」），收起状态也能看到当前筛选条件
- 展开/收起状态与筛选状态均持久化

### 影响分析

| 维度 | 影响 |
|---|---|
| 涉及文件 | `计时器.html`（+ `index.html` 同步）、`style.css`、`renderer.js` |
| 兼容性 | 所有元素 `id` 保持不变，不破坏 `renderer.js` 的事件绑定 |
| 交互逻辑 | 筛选下拉菜单从"绝对定位下拉"改为在折叠面板内正常布局（规避 `.collapsible-content` 的 `max-height` + `overflow:hidden` 裁剪问题） |
| 数据 | 无数据格式变更，无迁移需求 |
| 风险 | 元素 ID 缺失会导致绑定失败 → 通过引用完整性校验规避 |

### 验证结果

- ✅ 语法检查通过
- ✅ 元素引用完整性校验：HTML 中 id 与 JS 引用全部匹配
- ✅ 运行时探针确认：`toolPanel`、`toolPanelSummary`、各按钮与函数均就位；摘要显示"卡片 · 本周"
- ✅ 启动冒烟测试通过

## CR-002 · 悬浮窗显示任务图片 + 内容开关

| 项 | 内容 |
|---|---|
| **提出日期** | 2026-09-11 |
| **提出人** | 项目所有者 |
| **类型** | 功能新增 |
| **优先级** | 中 |
| **状态** | ✅ 已完成 |

### 变更理由

任务内容本身是 HTML，可包含图片，但悬浮窗用 `stripHtml()` 把内容强制转为纯文本，图片完全无法显示。用户希望悬浮窗能展示任务中的图片，并提供开关控制。

### 变更内容

| 功能 | 说明 |
|---|---|
| 显示任务图片 | 从当前任务 `content` 的 HTML 中提取 `<img>`，在任务文字下方渲染为缩略图 |
| 数量上限 | 超出上限的部分显示 `+N` 角标 |
| 点击放大 | 点击图片在悬浮窗内临时放大，再点一次还原 |
| 开关 1：显示任务 | 关闭后任务区与分隔线一起隐藏，悬浮窗只剩时钟 |
| 开关 2：显示任务图片 | 关闭后只显示文字 |
| 设置项 3：最多显示图片 | 1–6 张，默认 3 |
| 自动撑高 | 开启图片且窗口高度 <160px 时自动调整到 170px，保证图片可见 |

设置入口：主界面 **⚙ → 悬浮窗设置**。

### 影响分析

| 维度 | 影响 |
|---|---|
| 涉及文件 | `float.html`、`计时器.html`（+ `index.html` 同步）、`renderer.js`、`main.js`、`style.css` |
| 新增 localStorage 键 | `floatShowTask`、`floatShowImages`、`floatImageLimit` |
| 新增 IPC 频道 | `float-content-settings`（主 → 悬浮窗）、`update-float-content-settings`（渲染 → 主） |
| 同步方式 | 沿用既有"设置存主窗口 localStorage → 主进程 `executeJavaScript` 读取 → 推送悬浮窗"模式 |
| 窗口约束 | 未修改 150–700 × 50–250 的范围限制；新增 `ensureFloatWindowFitsImages()` 做高度兜底 |
| 风险 | 图片提取需正确处理 `file://` 路径与相对路径两种 src |

### 验证结果

- ✅ `float.html` 内联脚本语法检查通过
- ✅ 悬浮窗独立运行时测试：图片成功真实加载（实测渲染宽度 1052px）
- ✅ 开关逻辑验证：关闭任务区后任务区正确隐藏
- ✅ 主界面初始化探针确认三个设置控件全部就位

### 文档更新

需求 → `03` FR-5.11 / 5.12 / 5.13 / 5.14 / 5.15 ｜ 架构 → `02` §3.2 ｜ 进度 → `05` M7

## CR-006 · 消除双 HTML 漂移隐患（✅ 已完成 2026-09-11）

| 项 | 内容 |
|---|---|
| **类型** | 重构 |
| **优先级** | **P0** |
| **状态** | ✅ 已完成（采用方案 A） |

### 变更理由

`main.js` 实际加载的是 `计时器.html`，但仓库中同时存在内容基本一致的 `index.html`。两者必须手工同步，极易漂移——一旦有人修改了 `index.html`，会得到"改了没生效"的困惑。

### 候选方案

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A（已采用）** | 删除 `index.html`，在 README 与文档中明确"主界面只有 `计时器.html`" | 彻底消除隐患，最简单 | 需确认无外部引用 |
| B | 保留 `index.html` 作为软链接 / 构建时拷贝 | 兼容按惯例找 `index.html` 的工具 | Windows 下软链需权限 |
| C | 增加构建前校验脚本，检测两份文件是否一致 | 保留双份 | 未从根本解决，仍需同步 |

### 影响分析

| 维度 | 影响 |
|---|---|
| 涉及文件 | `index.html`（已删除）；`main.js` 加载路径**无需修改**（本就加载 `计时器.html`） |
| 风险 | 已全仓搜索，无任何代码 / 脚本 / 打包配置引用 `index.html` |

### 实施与验证

| 步骤 | 结果 |
|---|---|
| 全仓搜索引用 | 仅文档与 `README` 提及，代码零引用 ✅ |
| `package.json` / `electron-builder` 配置引用 | 无 ✅ |
| 删除前一致性检查 | 两份 HTML **已不一致**（md5 不同）—— 恰好实证了漂移已经发生 |
| `git rm index.html` | 已删除 ✅ |
| 语法检查 | `main.js` / `renderer.js` / `float.html` / `计时器.html` 全部通过 ✅ |
| 启动验证 | 主窗口与悬浮窗均正常加载 ✅ |

### 结论

`index.html` 已从仓库移除。**主界面 HTML 从此只有 `计时器.html` 一份**，`01` / `02` / `04` / `05` / `08` / `09` 等文档中所有"双 HTML 需同步"的表述已同步清理。删除它时两份文件的内容已经不一致，说明这个隐患在此之前就已经实际发生了。

### 影响分析

| 维度 | 影响 |
|---|---|
| 涉及文件 | `计时器.html`（新增开关 UI）、`renderer.js`（读写 `localStorage.autoStartNext` + IPC 推送）、`main.js`（`autoStartNext` 状态 + 归零分支逻辑 + `app.getVersion()`）、`float.html`（阴影实现） |

### 关键技术细节

```js
        mainWindow.webContents.send('timer-end', { isWorking: isWorking });
    }
    isWorking = !isWorking;
    currentTime = isWorking ? WORK_TIME : REST_TIME;

    if (autoStartNext) {
        // 不动 interval，让它继续跑下去；
        // 且不重置 lastTime，使不足 1 秒的余量带到下一阶段，避免累积漂移
    } else {
        clearInterval(timerInterval);
        timerInterval = null;
        isTimerRunning = false;
    }
    updateTrayMenu();
}
```

> `isRunning` 由 `timerInterval !== null` 推导，因此"保留 interval"本身就等于"仍在运行"，无需额外状态。

## CR-009 · WebHook 配置 API 化 + 单选枚举对齐（✅ 已完成 2026-09-30）

| 项 | 内容 |
|---|---|
| **类型** | 功能新增（API / CLI）+ 缺陷修复 |
| **优先级** | P1（AI/脚本无法自助接入表格，且企业微信智能表格持续同步失败） |
| **状态** | ✅ 已完成 |

### 变更理由

实际接入企微智能表格时，四件事连环卡住：

1. **字段 ID 只能靠人贴**：`POST /api/settings` 写的是渲染层 `store`，碰不到 `mainSettings.webhook`，
   AI/脚本没有任何入口配置 webhook（`GET /api/webhook` 也只回传少量信息），只能让人打开设置面板手点。
2. **示例 JSON 解析不出字段**：企微现行示例 JSON 的 `schema` 是**对象 map**（字段 ID 是 key，定义里只有 `title/type/enum`），
   而 `parseSchema` 只认「数组 + 字段自带 `field_id`」——用户按文档粘贴后点「解析字段」得到 0 列。
3. **枚举对不上会被整批拒收**：应用内部只产生 `高/中/低`、`已完成/未完成`，
   而表格枚举常是 `最高优/高优/低优`、`已完成/进行中/未启动/已逾期`，写入即 `2023010`。
4. **空日期被写成 2000-01-01**：`Date.parse('0')` 的副作用，表格里凭空多出错误时间。

### 变更内容

| 类别 | 内容 |
|---|---|
| **API 新增** | `POST /api/webhook` 支持 `{action:"config"}`（改配置）/ `{action:"parse"}`（只解析）/ `{action:"test"}`（发测试）/ 推送时 `force` 忽略开关；`GET /api/webhook` 返回完整配置（含每列 `enum` 选项、`mapping`、`constants`、`recordCount`） |
| **配置模型** | 新增 `constants`（字段 ID → 固定文本），用于「所属项目/所属部门/风险评估」这类内部无数据源的列；`mapping`/`constants`/`recordIds` 一律**合并**语义 |
| **数据源新增** | 设置面板与 CLI 的数据源下拉新增「固定文本」；`recordIds` 支持外部回填（`--record-ids-file`），避免绕过应用写入的记录被重复新增 |
| **枚举对齐** | 写入单选列前做「完全一致 → 包含关系 → 关键词规则」就近对齐，对不上则**跳过该列**（不再整批失败） |
| **UI** | 设置面板每列显示预设选项提示；映射为「固定文本」时出现输入框 |
| **CLI** | `timer-cli.js` / `timer-cli.py` 新增 `webhook config / set / parse / test` 与 `--force`；修 `delete/done/comment` 的 ID 格式化崩溃 |
| **缺陷修复** | ① `parseSchema` 支持对象 map 形态；② `guessSource` 规则顺序（`任务状态` 曾被判成任务内容）；③ 空日期列不再写入 2000-01-01 |
| **构建/部署** | 新增 `npm run build:dir` 与 `npm run deploy:local`（`scripts/deploy-local.js`）：构建产物 + 备份 + 就地覆盖安装目录，解决 R-13「`dist/` 与源码不同步」；部署前自动检测 `app.asar` 占用 |

## CR-010 · 表格视图列宽自适应 + 日期显示年份（✅ 已完成 2026-09-30）

| 项 | 内容 |
|---|---|
| **类型** | 优化（界面）+ 功能新增（设置项） |
| **优先级** | P2 |
| **状态** | ✅ 已完成 |

### 变更理由

用户反馈两条，都指向表格视图（`tableView`）：

1. **「我都改了宽度了，这个任务里面的字没有拉宽」**——设置里「整体界面宽度」调的是 `.container` 的 `max-width`，但表格视图「任务内容」单元格被两层写死的宽度锁住：CSS `.table-content{max-width:220px}` + 行内 `<td style="max-width:350px">`。所以容器再宽，文字永远在 220px 处换行。
2. **「创建时间有点错位」**——时间输出是一整串 `2026-09-29 18:45:31`，列一窄浏览器就从连字符处断开，变成 `2026-09-` / `29` / `18:45:31` 三行碎片；窄窗口下所有列一起被压扁。

### 变更内容

| 类别 | 内容 |
|---|---|
| 列宽自适应 | 移除 `.table-content{max-width:220px}` 与行内 `max-width:350px` / `word-break:break-all`；改为 `max-width:100%` + `min-width:200px`（内容列不再塌陷） |
| 折断修正 | 单词不再被 `break-all` 拦腰截断，改 `overflow-wrap:break-word` |
| 日期分段 | 新增 `formatDatePair()`：日期与时间各自 `white-space:nowrap`，**只在两者之间换行** → 宽列一行、窄列两行，不再出现碎片；`font-variant-numeric: tabular-nums` 让多行数字竖向对齐 |
| 表头 | `.task-table th` 加 `nowrap`，避免「创建时间」拆行 |
| 省宽 | 单元格内边距 `14×18` → `13×14`（7 列约省 56px）；操作列 `width:1%` 按内容收缩 |
| 太窄兜底 | `min-width:200px` + `.table-view-container{overflow-x:auto}`（配细滚动条样式）：真挤不下就横向滚动，而不是把每列压碎 |
| 设置新增 | 「日期显示年份」开关（`showYear`，默认开）：关掉后表格/卡片/提醒徽标统一显示 `09-30 18:45:31`；切换即时重绘，无需重启。归档分组标题仍保留年份（跨年辨认需要，且分组键独立于显示格式） |
