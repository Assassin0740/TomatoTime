## 2. 范围管理

### 2.1 范围说明书

**产品范围**：一个基于 Electron 的 Windows 桌面专注计时器，含主窗口（任务管理 + 计时）与悬浮窗（常驻显示）。

**项目范围（交付物）**

| 交付物 | 形态 | 状态 |
|---|---|---|
| 可运行的应用源码 | 源码仓库 | ✅ 已交付 |
| Windows 安装包 | `dist/` 下 NSIS 安装程序 | ✅ 已交付 |
| 项目文档库 | `项目文档/` 目录 | ✅ 本次交付 |

**明确排除（Out of Scope）**

- 云同步、账号系统、多端协同
- 移动端 / Web 版
- 数据统计分析报表
- 团队协作与任务指派
- 国际化多语言（界面为中文）

## 5. 沟通管理

| 沟通内容 | 对象 | 方式 | 频率 |
|---|---|---|---|
| 需求确认与方案选择 | 项目所有者 | 对话确认（关键决策提供选项） | 按需 |
| 变更影响说明 | 项目所有者 | 变更说明 + 影响分析 | 每次变更 |
| 交付物 | 项目所有者 | 文件呈现 | 每次交付 |
| 工作记录 | —— | `.workbuddy/memory/` 日志 | 每次实质工作后 |

**沟通原则**

1. **先确认再动手**：涉及方向性选择时，先给出选项征求确认，避免返工。
2. **不留悬念**：交付后明确说明改了什么、怎么看到效果、有什么遗留问题。
3. **风险透明**：发现的问题即使本次不修，也要明确列出。

## 6. 质量管理

### 6.1 质量目标

| 目标 | 度量 |
|---|---|
| 无启动即崩的错误 | 每次改动后启动验证通过 |
| 无语法 / 引用错误 | `node --check` + 元素 ID 引用校验通过 |
| 核心功能可运行 | 冒烟测试通过，关键断言全部成立 |
| 无数据丢失 | 涉及任务内容的改动必须有保图验证 |

### 6.2 质量控制手段

| 手段 | 说明 | 详见 |
|---|---|---|
| 语法检查 | `node --check main.js/renderer.js`，`float.html` 内联脚本语法解析 | `08` |
| 引用完整性校验 | 提取 HTML 中所有 `id` 与 JS 中 `getElementById` 引用比对 | `08` |
| 运行时冒烟测试 | 实际启动 Electron，读取渲染进程探针输出 | `08` |
| 悬浮窗专项测试 | 独立加载 `float.html`，验证图片渲染与编辑保图 | `08` |
| 变更后回归 | 修改 `计时器.html` 后校验元素 ID 未缺失 | 流程约定 |

### 6.3 质量验收标准（DoD · 完成的定义）

一个变更只有同时满足以下条件才算"完成"：

- [ ] 功能按需求实现
- [ ] 语法检查通过
- [ ] 元素引用无缺失
- [ ] 启动冒烟测试通过
- [ ] 若涉及任务内容 → 图片保留验证通过
- [ ] 若修改了 `计时器.html` → `index.html` 已同步
- [ ] 相关文档已更新
- [ ] 临时测试文件已清理
