# 11 · WebHook 同步表格（企业微信智能表格）

> 面向「配置这个功能的人」：怎么把计时器里的任务自动写进智能表格，以及踩过的坑。
> 创建日期：2026-09-28 ｜ 对应版本：v1.1.0 ｜ 相关代码：`webhook.js`、`main.js`、`renderer.js`

---

## 1. 一句话说明

任务有变化 → 应用按 6 秒一轮做差分 → 用企业微信智能表格的 Webhook
把任务写成表格里的一行（或更新已有的一行）。

```
计时器改动任务 ──▶ 主进程差分轮询 ──▶ 字段映射 ──▶ POST 智能表格 Webhook ──▶ 表格新增/更新记录
      (手动编辑 / AI 注入 / 右键手动推送 都算)
```

---

## 2. 智能表格那边怎么开

1. 打开智能表格 → 建好你想要的列（例如：任务内容、优先级、状态、类型、创建时间）
2. 右上角「自动化」→ 新建 → 触发条件选 **「接收到 Webhook 请求时」**
3. 复制它给出的地址，形如：

```
https://qyapi.weixin.qq.com/cgi-bin/wedoc/smartsheet/webhook?key=xxxxxx
```

4. 同一页面上有一份**示例 JSON**（里面带 `schema`，逐列描述 `field_id` / `field_name` / `field_type`）
   —— **整段复制**，第 3 步要用

   两种 `schema` 形态都支持（2026-09-30 修复）：

   ```jsonc
   // 形态 ①：数组 + 字段自带 id
   { "schema": [ { "field_id": "fA1", "field_name": "任务内容", "field_type": "text" } ] }

   // 形态 ②（企微现行示例 JSON）：对象 map，**字段 ID 就是 key**，定义里只有 title/type/enum
   { "schema": { "fqmfGP": { "title": "任务名称", "type": "text" },
                 "f04uVx": { "title": "优先级", "type": "single_select",
                             "enum": ["最高优", "高优", "低优"] } } }
   ```

   > 旧版本只认形态 ①，而企微现在给的是形态 ② —— 结果用户照着文档粘上去，点「解析字段」解析出 **0 列**，
   > 看起来像「粘错了」。已修。
5. 后续节点选「新增记录」，把请求体里的字段对应到你表格的列（字段 ID 会自动带出来）

> ⚠️ Webhook 地址 = 这张表的写入密钥，别贴到公开场合。应用里展示时会自动打码。

## 3. 应用这边怎么配

设置面板 →「🔗 WebHook · 同步到表格」：

| 项 | 说明 |
|---|---|
| 启用同步 | 总开关（默认开，地址为空时只记错误不打扰你） |
| 回调地址 | 粘贴上面那条含 `?key=` 的完整地址 |
| 推送时机 | 勾选要同步的事件：新增 / 完成 / 修改 / 归档 / 删除 |
| 载荷格式 | 默认「企业微信智能表格（add_records）」；其它格式用于自建服务或群机器人 |
| 示例 JSON | 粘贴「接收外部数据」页面给的示例 JSON |
| 解析字段 | 解析出列 → 自动按列名猜一份对应关系 |
| 列对应关系 | 每一列一个下拉框，选这条数据从哪来（也可选「不写入」） |
| 保存 / 发送测试 | 测试成功代表地址、字段 ID、映射都对 |
| 底部记录 | 最近 8 次推送的结果（时间、HTTP 状态或错误原因） |

映射下拉里可选的数据来源：
任务内容、优先级、状态、是否完成、类型、创建时间、完成时间、提醒时间、
评论、评论数、图片数、图片（base64）、图片地址、任务 ID、事件类型、
**固定文本**（2026-09-30 新增：给「所属项目/所属部门」这类内部没有数据源的列写死文本，右侧输入框填内容）。

自动猜测规则（可手动改）：

| 列名含 | 映射到 |
|---|---|
| 内容 / 标题 / 任务 / 待办 / 事项 / 描述 | 任务内容（**兜底规则，放最后**） |
| 优先级 / 重要程度 / 紧急 | 优先级 |
| 是否完成 / 已完成 / done | 是否完成（复选框） |
| 状态 / 完成情况 / 进度状态 | 状态（文本） |
| 图片数 / 附件数 | 图片数 |
| 图片 / 截图 | 图片（base64） |
| 创建 / 提交 / 建立 / 启动时间 / 开始时间 | 创建时间 |
| 完成时间 / 结束时间 | 完成时间 |
| 提醒 / 截止 / 到期 / due / deadline | 提醒时间 |
| 评论 / 备注 | 评论 |
| ID / 编号 / 序号 | 任务 ID |

> ⚠️ **规则顺序踩过的坑（2026-09-30 修复）**：旧顺序把「内容 / 任务」放在最前，
> 于是「**任务状态**」被猜成任务内容（因为它含「任务」二字）。现在具体规则全部前置、
> 「内容/任务」只做兜底；单选项还会把预设选项显示在列名后面，方便核对。

## 4. 企业微信 Webhook 的真实协议（重点）

请求体**必须是**下面这种结构，`values` 的 **key 是字段 ID（形如 `fABCD1`），不是列名**：

```json
{
  "add_records": [
    { "values": { "fABCD1": "写周报", "fABCD2": [{ "text": "高" }] } }
  ]
}
```

更新已有记录（只能更新「之前由 Webhook 写入」的记录）：

```json
{
  "update_records": [
    { "record_id": "REC_xxx", "values": { "fABCD3": [{ "text": "已完成" }] } }
  ]
}
```

字段值形态（按列类型）：

| 列类型 | 传法 |
|---|---|
| 文本 / 电话 / 邮箱 | 字符串 |
| 数字 / 货币 | 数字（不带引号） |
| 进度 / 百分比 | 0–100 的整数（30 表示 30%） |
| 复选框 | `true` / `false` |
| 日期时间 | **毫秒时间戳字符串**，如 `"1740806400000"` |
| 单选 | `[{ "text": "已完成" }]`（选项文本须与预设完全一致） |
| 多选 | `[{ "text": "前端" }, { "text": "后端" }]` |
| 图片 | `[{ "title": "a.png", "image_base64": "纯base64（不带 data:image 前缀）" }]` |
| 成员 | `[{ "user_id": "lisi" }]` 或 `["张三"]` |

限制：单表 ≤ 3000 条/分钟，单文档 ≤ 10000 条/分钟，**单请求 ≤ 500 条**（应用会自动分批）。
公式、自动编号、查找引用、关联、创建人、创建时间等列不支持写入，应用会自动跳过。

## 5. 事件与「更新」是怎么判断的

| 事件 | 触发条件 | 请求体 |
|---|---|---|
| `created` | 出现新任务 | `add_records` |
| `completed` | 任务从「未完成」变成「已完成」 | 有 record_id 时 `update_records`，否则 `add_records` |
| `updated` | 内容 / 优先级 / 类型 / 评论 变化 | 同上 |
| `archived` | 任务进入归档历史 | 同上 |
| `deleted` | 任务被删除 | 同上（只有 ID 可用） |

应用每 6 秒读一次任务快照并与上一轮比对，**首次只建立快照、不推送**（否则一开程序就会把历史任务全推一遍）。
推送成功且响应里带 `record_id` 时，应用会把它记住，之后该任务的「完成 / 修改」就会变成 `update_records`。

除自动同步外，还可以手动推：

- 任务卡片上右键 →「推送到表格」（无论事件订阅是否勾选，都会推这一条）
- API：`POST /api/webhook { "action": "created", "ids": [任务ID] }`

## 5.5 枚举对齐与固定文本（2026-09-30 增加）

### 为什么需要「枚举对齐」

表格里的单选列通常长这样：

| 列 | 表格预设选项 | 应用内部只会产生 |
|---|---|---|
| 优先级 | 最高优 / 高优 / 低优 | 高 / 中 / 低 |
| 任务状态 | 已完成 / 进行中 / 未启动 / 已逾期 | 已完成 / **未完成** |

直接把内部值写进去，企业微信用 `2023010`（选项值不合法）**拒收整批**。
所以现在写入前会做一次「就近对齐」：

1. 完全一致 → 直接用；
2. 选项包含内部值（`高` → `高优`）→ 取**最短**的那个（避免误选「最高优」）；
3. 内部值包含选项 → 取最长的；
4. 关键词规则：`未完成` → `进行中`、`最高` → `最高优`、`低` → `低优` …；
5. 还对不上 → **跳过这一列**（宁可少写一列，也不让整批失败）。

### 固定文本列

「所属项目」「所属部门」「AI 风险评估」这类列，内部数据源里没有对应值。
现在数据源下拉里有「**固定文本**」，选中后右侧输入框填死文本即可：`所属项目 = 拯救小猫`。
它是单选项时同样会走上面的枚举对齐。

### 空值不再写成 2000-01-01

旧实现里，任务没有截止/完成时间时，日期列会被 `Date.parse('0')` 解析成 `2000-01-01` 写进表格。
现在数值 0 / 空值直接跳过该列。

### 全部可用 API 配置（不用再点设置面板）

见 [`10-AI接入API.md` 第 8 节](10-AI接入API.md)：`POST /api/webhook` 支持
`{action:"config"}` 改配置、`{action:"parse"}` 只解析、`{action:"test"}` 发测试；
`GET /api/webhook` 返回完整配置（含每列选项）。命令行等价物：

```bash
node timer-cli.js webhook parse --schema-file schema.json
node timer-cli.js webhook set --enable --schema-file schema.json \
    --map fqmfGP=content --map f04uVx=priority --map f8o4LT=const --const f8o4LT=拯救小猫
node timer-cli.js webhook config        # 看当前映射与选项
node timer-cli.js webhook test          # 发一条测试记录
```

> `recordIds` 回填：如果记录是**绕过应用**直接推给企微的（脚本/别的工具），
> 应用并不知道 `record_id`，之后勾「完成」会新增重复行。
> 用 `--record-ids-file ids.json`（`{任务ID: record_id}` 或 `[{taskId, recordId}]`）把 ID 喂回来即可。

## 6. 出错对照表

| 现象 / 返回 | 原因与处理 |
|---|---|
| `40058 invalid Request Parameter` | 请求体不是 `add_records` / `update_records` 结构（例如错用了 `records` / `fields`）。把载荷格式切回「企业微信智能表格」 |
| `2022004 field not exists` | 字段 ID 不对：重新粘贴示例 JSON 并「解析字段」 |
| `2023010` 选项值不合法 | 单选/多选列的文本与表格预设不完全一致（含大小写、空格）。2026-09-30 起应用会自动对齐枚举，仍报此错说明该列对不上（应用会跳过它而不是让整批失败）；核对列名后面显示的「选项」 |
| `2023033` | 图片 base64 带了 `data:image/...;base64,` 前缀（应用已自动去掉） |
| `40014` key 无效或过期 | 重新在「接收外部数据」页面获取地址 |
| `45033` 超频 | 会自动分批，必要时减少勾选的事件 |
| 记录里显示「还没解析表格字段」 | 还没粘贴示例 JSON，字段 ID 无从得知（或用 `POST /api/webhook {action:"config",config:{schemaJson}}` 远程写入） |
| 记录里显示「这一批没有可写入的字段」 | 所有列都选了「不写入」，或列类型不支持 |

应用侧的错误都会写进设置面板底部的推送记录，包含时间、HTTP 状态与 `errmsg`。

## 7. 其它载荷格式（非智能表格）

在「载荷格式」里切换即可，适合推给自建服务或企业微信群机器人：

| 格式 | 请求体 |
|---|---|
| 通用 records 数组 | `{ action, event, timestamp, count, records: [ {列名: 值} ] }` |
| 通用字段平铺 | `{ action, event, timestamp, 列名: 值 }` |
| 群机器人文本 | `{ msgtype: "text", text: { content: "..." } }` |
| 自定义模板 | 自己写 JSON，`{{任务内容}} {{优先级}} {{状态}} {{records}} {{json}}` 会被替换（值自动做 JSON 转义） |

通用格式的「列名映射」在同一个面板里，按 `列名=数据源` 每行一条填写。
