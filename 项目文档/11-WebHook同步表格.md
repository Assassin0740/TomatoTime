# 11 · WebHook 同步表格（企业微信智能表格）

> 面向「配置这个功能的人」：怎么把计时器里的任务自动写进智能表格，以及踩过的坑。
> 创建日期：2026-09-28 ｜ 对应版本：v1.1.0 ｜ 相关代码：`webhook.js`、`main.js`、`renderer.js`

---

## 1. 一句话说明

任务有变化 → 应用按 6 秒一轮做差分 → 用企业微信智能表格的 Webhook
把任务写成表格里的一行（或更新已有的一行）。

```
计时器改动任务 ──▶ 主进程差分轮询 ──▶ 字段映射 ──▶ POST 智能表格 Webhook ──▶ 表格新增/更新记录
      (手动编辑 / AI 注入 / 右键手动推送 都算)
```

---

## 2. 智能表格那边怎么开

1. 打开智能表格 → 建好你想要的列（例如：任务内容、优先级、状态、类型、创建时间）
2. 右上角「自动化」→ 新建 → 触发条件选 **「接收到 Webhook 请求时」**
3. 复制它给出的地址，形如：

```
https://qyapi.weixin.qq.com/cgi-bin/wedoc/smartsheet/webhook?key=xxxxxx
```

4. 同一页面上有一份**示例 JSON**（里面带 `schema`，包含每列的 `field_id` / `field_name` / `field_type`）
   —— **整段复制**，第 4 步要用
5. 后续节点选「新增记录」，把请求体里的字段对应到你表格的列（字段 ID 会自动带出来）

> ⚠️ Webhook 地址 = 这张表的写入密钥，别贴到公开场合。应用里展示时会自动打码。

---

## 3. 应用这边怎么配

设置面板 →「🔗 WebHook · 同步到表格」：

| 项 | 说明 |
|---|---|
| 启用同步 | 总开关（默认开，地址为空时只记错误不打扰你） |
| 回调地址 | 粘贴上面那条含 `?key=` 的完整地址 |
| 推送时机 | 勾选要同步的事件：新增 / 完成 / 修改 / 归档 / 删除 |
| 载荷格式 | 默认「企业微信智能表格（add_records）」；其它格式用于自建服务或群机器人 |
| 示例 JSON | 粘贴「接收外部数据」页面给的示例 JSON |
| 解析字段 | 解析出列 → 自动按列名猜一份对应关系 |
| 列对应关系 | 每一列一个下拉框，选这条数据从哪来（也可选「不写入」） |
| 保存 / 发送测试 | 测试成功代表地址、字段 ID、映射都对 |
| 底部记录 | 最近 8 次推送的结果（时间、HTTP 状态或错误原因） |

映射下拉里可选的数据来源：
任务内容、优先级、状态、是否完成、类型、创建时间、完成时间、提醒时间、
评论、评论数、图片数、图片（base64）、图片地址、任务 ID、事件类型。

自动猜测规则（可手动改）：

| 列名含 | 映射到 |
|---|---|
| 内容 / 标题 / 任务 / 待办 / 事项 / 描述 | 任务内容 |
| 优先级 / 重要程度 / 紧急 | 优先级 |
| 是否完成 / 已完成 / done | 是否完成（复选框） |
| 状态 / 完成情况 | 状态（文本） |
| 图片数 / 附件数 | 图片数 |
| 图片 / 截图 | 图片（base64） |
| 创建 / 提交 / 建立 | 创建时间 |
| 完成时间 / 结束时间 | 完成时间 |
| 提醒 / 截止 / due | 提醒时间 |
| 评论 / 备注 | 评论 |
| ID / 编号 / 序号 | 任务 ID |

## 4. 企业微信 Webhook 的真实协议（重点）

请求体**必须是**下面这种结构，`values` 的 **key 是字段 ID（形如 `fABCD1`），不是列名**：

```json
{
  "add_records": [
    { "values": { "fABCD1": "写周报", "fABCD2": [{ "text": "高" }] } }
  ]
}
```

更新已有记录（只能更新「之前由 Webhook 写入」的记录）：

```json
{
  "update_records": [
    { "record_id": "REC_xxx", "values": { "fABCD3": [{ "text": "已完成" }] } }
  ]
}
```

字段值形态（按列类型）：

| 列类型 | 传法 |
|---|---|
| 文本 / 电话 / 邮箱 | 字符串 |
| 数字 / 货币 | 数字（不带引号） |
| 进度 / 百分比 | 0–100 的整数（30 表示 30%） |
| 复选框 | `true` / `false` |
| 日期时间 | **毫秒时间戳字符串**，如 `"1740806400000"` |
| 单选 | `[{ "text": "已完成" }]`（选项文本须与预设完全一致） |
| 多选 | `[{ "text": "前端" }, { "text": "后端" }]` |
| 图片 | `[{ "title": "a.png", "image_base64": "纯base64（不带 data:image 前缀）" }]` |
| 成员 | `[{ "user_id": "lisi" }]` 或 `["张三"]` |

限制：单表 ≤ 3000 条/分钟，单文档 ≤ 10000 条/分钟，**单请求 ≤ 500 条**（应用会自动分批）。
公式、自动编号、查找引用、关联、创建人、创建时间等列不支持写入，应用会自动跳过。

---

## 5. 事件与「更新」是怎么判断的

| 事件 | 触发条件 | 请求体 |
|---|---|---|
| `created` | 出现新任务 | `add_records` |
| `completed` | 任务从「未完成」变成「已完成」 | 有 record_id 时 `update_records`，否则 `add_records` |
| `updated` | 内容 / 优先级 / 类型 / 评论 变化 | 同上 |
| `archived` | 任务进入归档历史 | 同上 |
| `deleted` | 任务被删除 | 同上（只有 ID 可用） |

应用每 6 秒读一次任务快照并与上一轮比对，**首次只建立快照、不推送**（否则一开程序就会把历史任务全推一遍）。
推送成功且响应里带 `record_id` 时，应用会把它记住，之后该任务的「完成 / 修改」就会变成 `update_records`。

除自动同步外，还可以手动推：

- 任务卡片上右键 →「推送到表格」（无论事件订阅是否勾选，都会推这一条）
- API：`POST /api/webhook { "action": "created", "ids": [任务ID] }`

## 6. 出错对照表

| 现象 / 返回 | 原因与处理 |
|---|---|
| `40058 invalid Request Parameter` | 请求体不是 `add_records` / `update_records` 结构（例如错用了 `records` / `fields`）。把载荷格式切回「企业微信智能表格」 |
| `2022004 field not exists` | 字段 ID 不对：重新粘贴示例 JSON 并「解析字段」 |
| `2023010` 选项值不合法 | 单选/多选列的文本与表格预设不完全一致（含大小写、空格） |
| `2023033` | 图片 base64 带了 `data:image/...;base64,` 前缀（应用已自动去掉） |
| `40014` key 无效或过期 | 重新在「接收外部数据」页面获取地址 |
| `45033` 超频 | 会自动分批，必要时减少勾选的事件 |
| 记录里显示「还没解析表格字段」 | 还没粘贴示例 JSON，字段 ID 无从得知 |
| 记录里显示「这一批没有可写入的字段」 | 所有列都选了「不写入」，或列类型不支持 |

应用侧的错误都会写进设置面板底部的推送记录，包含时间、HTTP 状态与 `errmsg`。

## 7. 其它载荷格式（非智能表格）

在「载荷格式」里切换即可，适合推给自建服务或企业微信群机器人：

| 格式 | 请求体 |
|---|---|
| 通用 records 数组 | `{ action, event, timestamp, count, records: [ {列名: 值} ] }` |
| 通用字段平铺 | `{ action, event, timestamp, 列名: 值 }` |
| 群机器人文本 | `{ msgtype: "text", text: { content: "..." } }` |
| 自定义模板 | 自己写 JSON，`{{任务内容}} {{优先级}} {{状态}} {{records}} {{json}}` 会被替换（值自动做 JSON 转义） |

通用格式的「列名映射」在同一个面板里，按 `列名=数据源` 每行一条填写。
