# 03 · 需求规格说明书（SRS）

> **文档性质**：描述系统**应当具备什么能力**，作为开发、测试与验收的共同基准。
> **说明**：本文件是对**现有已实现功能**的逆向梳理（As-Built）+ 已确认的待办需求。
> 状态标记：✅ 已实现 ｜ 🔄 进行中 ｜ 📋 已确认待实现 ｜ 💡 建议（待定）

---

## 1. 需求概述

### 1.1 产品定位

一款面向个人用户的 **Windows 桌面专注计时器**。核心价值：用番茄工作法帮助用户保持专注，同时提供轻量的待办管理，并通过**桌面悬浮窗**让剩余时间与当前任务始终可见。

### 1.2 目标用户

| 用户画像 | 特征 | 核心诉求 |
|---|---|---|
| 学生 / 自学者 | 需要长时间专注，任务碎片化 | 计时提醒 + 待办记录 |
| 远程办公者 | 桌面常驻多个窗口 | 悬浮窗不遮挡、可穿透 |
| 任务管理爱好者 | 关注优先级与归档 | 优先级 / 类型 / 归档 / 导出 |

### 1.3 需求范围

**范围内**：单机、本地存储、无需登录、无需网络。

**范围外（明确不做）**：
- ❌ 多设备云同步
- ❌ 团队协作 / 任务指派
- ❌ 账号体系与登录
- ❌ 移动端应用
- ❌ 数据统计报表（暂无此需求）

## 3. 主要用例

### UC-01 完成一个专注周期

| 项 | 内容 |
|---|---|
| 参与者 | 用户 |
| 前置条件 | 应用已启动 |
| 主流程 | 1. 用户输入任务并添加 → 2. 点击开始 → 3. 计时器倒计时 → 4. 主窗口/悬浮窗同步显示 → 5. 归零播放提示音并切到休息 → 6. 休息结束再切回工作 |
| 后置条件 | 任务仍在列表中，计时器处于新阶段待开始 |
| 异常流 | 用户中途暂停 → 计时停止，状态保持不变，可再次开始 |

### UC-02 通过悬浮窗管理任务

| 项 | 内容 |
|---|---|
| 参与者 | 用户 |
| 前置条件 | 悬浮窗已开启 |
| 主流程 | 1. 悬浮窗显示当前任务与图片 → 2. 用户点击任务文字 → 3. 进入编辑态 → 4. 修改后回车 → 5. 主窗口数据更新 → 6. 悬浮窗回显新内容（图片仍在） |
| 异常流 | 若任务含图片，编辑后必须保留图片（FR-8.1） |

### UC-03 归档已完成任务

| 项 | 内容 |
|---|---|
| 参与者 | 用户 |
| 主流程 | 1. 勾选若干任务 → 2. 点击"归档已完成" → 3. 提示归档数量 → 4. 任务移入归档历史 → 5. 活跃列表刷新 |
| 异常流 | 无已完成任务 → 提示"当前活跃列表中没有已完成的任务" |

### UC-04 自定义外观并同步到悬浮窗

| 项 | 内容 |
|---|---|
| 参与者 | 用户 |
| 主流程 | 1. 打开设置面板 → 2. 调整颜色 / 发光 / 阴影 → 3. 主窗口即时生效 → 4. 通过 IPC 同步到悬浮窗 → 5. 悬浮窗即时生效 |

## 4. 非功能需求（Non-Functional Requirements）

| 编号 | 类别 | 需求 | 指标 / 说明 |
|---|---|---|---|
| NFR-1 | 性能 | 应用启动到可交互 | 冷启动 ≤ 3 秒（本地 SSD） |
| NFR-2 | 性能 | 任务列表渲染 | 100 条任务下滚动流畅，采用懒加载与增量渲染 |
| NFR-3 | 性能 | 计时精度 | 长时运行累计漂移 < 1 秒 / 小时 |
| NFR-4 | 可靠性 | 配置写入 | 采用原子写入，崩溃不损坏配置 |
| NFR-5 | 可靠性 | 数据安全 | 任务图片不得因编辑操作丢失 |
| NFR-6 | 可用性 | 界面层级 | 主界面首屏仅保留高频操作，低频控件折叠 |
| NFR-7 | 兼容性 | 平台 | Windows 10 / 11（主要）；macOS 有部分适配代码 |
| NFR-8 | 可维护性 | 代码组织 | 无构建流程，改完即运行 |
| NFR-9 | 安全 | 权限模型 | 当前渲染进程拥有 Node 权限（**已知债务 TD-04**） |
| NFR-10 | 可移植性 | 数据迁移 | 支持 JSON 导入导出 |
